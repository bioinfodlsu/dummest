# Provisional Frameshift Rates

> **Disclaimer:** This document was generated by GPT-5.6-Luna and should be
> reviewed against the source code and calibration data before being treated
> as authoritative.

`tools/get_indel_rates.py` extracts 1-base and 2-base insertion/deletion
rates from a Badread error model.

## Current approximation

The following values are provisional:

```cpp
const Float INSERT1 = 0.0171;
const Float INSERT2 = 0.0018;
const Float DELETE1 = 0.0328;
const Float DELETE2 = 0.0083;
```

They come from the Badread `nanopore2020` model at **90% target identity**:

```text
1-insertion: 1.709757% per reference base -> 0.0171
2-insertion: 0.175268% per reference base -> 0.0018
1-deletion:  3.279012% per reference base -> 0.0328
2-deletion:  0.828603% per reference base -> 0.0083
```

Run the extractor with an explicit Badread checkout and model:

```bash
BADREAD_ROOT=/path/to/Badread
python3 tools/get_indel_rates.py \
  --badread-root "$BADREAD_ROOT" \
  --model "$BADREAD_ROOT/badread/error_models/nanopore2020.gz" \
  --identity 90
```

If Badread is installed as a Python package, `--badread-root` and `--model`
can be omitted.  Alternatively, set `BADREAD_ROOT` in the environment.

The script estimates empirical event proportions from the k-mer alternatives,
then scales those proportions by the requested overall error rate.  Its output
is an **occurrence rate per reference base**, not a probability for one HMM
transition.

This is intentionally a **rough approximation for now**.  It is useful for
initial experiments and reproducing the existing constants, but it should not
be treated as a validated generative model of DUMMER's background HMM.

## HMM compatibility warning

DUMMER's background model normally consumes a codon and can instead consume
one or two DNA bases.  The current code groups the rates by frame phase:

```text
one-base branch = INSERT1 + DELETE2
two-base branch = INSERT2 + DELETE1
```

That grouping does not preserve whether an event was an insertion or a
deletion.  It is only appropriate if the model intentionally represents the
net frame phase and not event direction.  Also, the extracted rates are per
base while the HMM branch is selected at a codon-sized opportunity.  Using
the rates directly as branch probabilities therefore has not been calibrated
to a target identity.

The `90,98,5` Badread identity range does not produce one universal rate: the
values above describe the 90% endpoint only.

## Suggested improvements

When the approximation needs to become a calibrated model:

1. Simulate long Badread reads at each target identity and measure indels from
   reference/read alignments rather than scaling the static error profile.
2. Convert per-base hazards to codon-level branch probabilities explicitly,
   including the possibility of multiple events within a codon-sized window.
3. Keep insertion and deletion directions separate unless only frame phase is
   needed by the HMM.
4. Include events longer than two bases and context-dependent rates in the
   calibration data.
5. Fit or validate the HMM branch probabilities against simulated sequence
   length, identity, indel-length, and frame-offset distributions.

Until those checks are done, do not describe the four constants as measured
HMM transition probabilities.

## Reproducibility note

The extractor imports Badread's `align_kmers` helper and reads its compressed
error-model file.  Keep the Badread version and model file recorded alongside
any results.  Badread is GPL-licensed; consult its license when redistributing
the helper or a modified copy.
